# 原因未明：三个经典样例

## 使用说明

依据 `backend/app/prompts/generate_teaching.md` 当前版本编写。本文为人工评审用构造样例，输入采用摘要；只有推荐 JSON 面向学生。动作已经由后端给定，均未触发解析展示阈值。

“原因未明”表示无法可靠解释当前卡点，不等同于 `latestEvaluation.correctness = UNCERTAIN`。本项目中，评价为 `UNCERTAIN` 时走确定性人工复核分支，不调用本教学生成器。因此，下面三个样例均使用“当前已表达内容可确认正确，但解释不完整”的有效教学场景；未知的是未完成的原因。

本模块分别覆盖信息过少、历史证据不足以区分候选、题目呈现材料可能不一致。每次仅澄清一个关键信息，不强迫学生自我诊断，也不因分类不明自动升级教学动作。

## 样例 1：只复述了数据并说“不会”，无法定位卡点

### 输入与约束

- 题目：出租车3千米以内收费10元，超过3千米的部分每千米收费2元。本次行驶8千米，求车费。
- `task.currentStudentText`：「题里说3千米以内10元，一共走8千米。我不知道怎么做。」
- `latestEvaluation`：`CORRECT + INCOMPLETE`；已复述部分已知条件，没有可确认的错误；超出部分的收费关系和计算均未讲出。
- 已提供历史：无。
- 当前目标：确认学生如何理解起步收费条件。
- `allowedAction`：`ASK_FOCUSED_QUESTION`。
- `doNotRepeat`：无；`doNotReveal`：不解释收费规则的答案、不算超出里程、不提供车费式子；`responseGoal`：补充最小的题意理解证据。

### 判断依据

保持“原因未明”。“我不知道怎么做”可能来自题意、知识、应用或表达，当前没有足够证据优先归入其中一类。先澄清题干关键条件，不将所有原因逐一问遍。

### 推荐输出

```json
{
  "content": "先从题目里这一条收费规定开始。",
  "questions": [
    {
      "id": "unclear_01",
      "question": "你怎样理解“3千米以内收费10元”这句话？"
    }
  ]
}
```

### 后续观察与质量标准

- 若认为起步范围内每千米收10元，出现具体题意误读证据；后续才据此调整假设。
- 若准确说明这一段路程共收费10元，排除了一个局部疑点，但超出部分的理解和建模仍待观察。
- 不合格写法：“你是不懂题意还是不会分段函数？”要求学生自行分类，并引入当前任务不需要的术语。

## 样例 2：能复述公式和步骤，却缺少独立解释证据

### 输入与约束

- 题目：方程 `2(x＋3)＝14`，求 x，并说明每一步依据。
- `task.currentStudentText`：「两边先同时除以2，得到x+3=7。下一步我还没写。」
- `latestEvaluation`：`CORRECT + INCOMPLETE`；当前变形正确，依据解释和后续求解仍缺失，没有已确认的错误。
- 已提供历史：先前教学已经明确提示“两边同时除以2”；学生随后曾回答“等式两边做相同运算”，但未说明操作如何使等式保持成立。
- 当前目标：验证对当前等式变形依据的理解。
- `allowedAction`：`ASK_FOCUSED_QUESTION`。
- `doNotRepeat`：不再提示两边除以2，不重复检查中间结果；`doNotReveal`：不先解释等式性质，不提示下一步求解或最终 x；`responseGoal`：获得比复述操作更有区分力的依据说明。

### 判断依据

保持“原因未明”。当前操作与先前提示一致，不能确认是理解后应用、跟随提示，还是仅省略解释。最多保留“表达与输入问题”和“知识理解与回忆问题”两个候选，本轮只检查等式变形依据。

### 推荐输出

```json
{
  "content": "你已经按前面的提示写出了x+3=7。接着只说明这一步成立的依据。",
  "questions": [
    {
      "id": "unclear_02",
      "question": "为什么原等式两边同时除以2后，两边仍然相等？"
    }
  ]
}
```

### 后续观察与质量标准

- 若能用等量各取一半等方式解释，增加对本步理解的支持，但操作本身已由历史提示，不能标记为独立发现解法。
- 若只重复“两边同时除以2”，仍不能区分候选原因，应保持不确定，避免把相同问题换措辞反复追问。
- 不合格写法：“你已经完全掌握等式性质。”现有证据主要是跟随提示和复述，无法支持这一结论。

## 样例 3：题目有图形标注，学生却报告看不到对应信息

### 输入与约束

- 题目：求梯形ABCD的面积。题目文字给出两条平行边长6厘米和10厘米；图示应通过直角标记表明内部线段EF是高，并在EF旁标4厘米。
- `task.currentStudentText`：「面积是上底加下底，再乘高，除以2。我能看到6和10，图里的4挤在边上，我看不出它标在哪条线上。」
- `latestEvaluation`：`CORRECT + INCOMPLETE`；面积公式表述正确，未确定高并完成代入，没有可确认的学生概念错误。
- 已提供历史：无；上下文没有学生端实际渲染截图，也没有证据证明其看到的图与原始图清晰度一致。
- 当前目标：澄清学生实际可辨认的图形标记。
- `allowedAction`：`ASK_FOCUSED_QUESTION`。
- `doNotRepeat`：无；`doNotReveal`：不告知哪条线段是高、不提供高的数值或面积答案；`responseGoal`：补充可见材料信息，暂缓归因。

### 判断依据

保持“原因未明”。可能是图形识读问题，也可能是显示或题目材料问题；不能仅依据生成器拿到的原始题目，断言学生看到的内容完整清晰。当前评价只确认学生已说出的公式正确，不保证原图呈现无误。

### 推荐输出

```json
{
  "content": "你已经说清了面积公式；目前还缺少你在图上实际能辨认的信息。",
  "questions": [
    {
      "id": "unclear_03",
      "question": "图中的直角标记旁，你能辨认出哪些线段名称？"
    }
  ]
}
```

### 后续观察与质量标准

- 若能报告直角标记及其相邻线段，可据此进一步区分图形知识和应用问题；不能直接当作已确定高。
- 若连标记或字母都看不清，增加材料呈现问题的可能性。只记录学生描述，不替后端宣布图错、改题或更改业务状态。
- 若后续独立评价变为 `UNCERTAIN`，应由既有规则处理；本文不为该结果伪造教学生成调用。
- 不合格写法：“4就是高，直接代公式。”既忽略材料问题，又交出了当前需要识别的信息。

## 合理性批判与不足

1. 保留不确定性能减少误标签，但连续澄清也会增加负担。问题必须能改变下一步帮助，否则应重新检查题目材料或当前调查方向。
2. 学生对界面的描述只能提供线索，不能确认具体渲染故障；第三例也没有实现图片诊断或人工处理流程，不能把观察标准当作系统已有能力。
3. 这些样例展示了如何获取证据，尚未通过真实学生对话检验区分效果；“原因未明”也不应成为不分析已有证据的固定选择。
