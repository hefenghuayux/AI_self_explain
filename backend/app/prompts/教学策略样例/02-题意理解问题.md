# 题意理解问题：三个经典样例

## 使用说明

依据 `backend/app/prompts/generate_teaching.md` 当前版本编写，供人工评审。场景为构造样例，输入为 TeachingContext 的阅读摘要；只有 JSON 是学生可见输出。后端已经给定动作，均未触发解析展示阈值。原因判断是本轮假设，不能成为学生长期标签。

本模块覆盖比较对象、数量限定词、所求对象三种不同误读。纠错只指出已确认的条件冲突，随后让学生用自己的话重述相关题意，不在问题中交出正确关系。

## 样例 1：百分数应用题，比较对象读反

### 输入与约束

- 题目：图书角有科技书80本，故事书比科技书多25%，求故事书的本数。
- `task.currentStudentText`：「故事书是拿来比较的那一份，科技书比故事书多25%。」
- `latestEvaluation`：`WRONG + INCOMPLETE`；学生将题干的比较方向读反，尚未正确建立数量关系。
- 已提供历史：无。
- 当前目标：澄清“故事书比科技书多25%”的比较关系。
- `allowedAction`：`CORRECT_AND_ASK`。
- `doNotRepeat`：无；`doNotReveal`：不说单位“1”、计算式和最终本数；`responseGoal`：确认学生如何理解题干原句。

### 判断依据

优先假设为“题意理解问题”，候选为“知识理解与回忆问题”。学生主动复述出反向关系，为题意误读提供了直接证据；仍不能据此排除百分数比较意义没有理解。

### 推荐输出

```json
{
  "content": "你说“科技书比故事书多25%”，与题干“故事书比科技书多25%”的比较方向相反。",
  "questions": [
    {
      "id": "meaning_01",
      "question": "请用自己的话说明题干中“故事书比科技书多25%”的意思。"
    }
  ]
}
```

### 后续观察与质量标准

- 能说明故事书比科技书多出科技书数量的四分之一，支持已澄清题意；尚未证明能独立列式。
- 只把原句照读一遍，无法区分理解与复述，不能当作有效验证。
- 不合格写法：“科技书是单位1，所以该用谁乘25%？”已给出关键关系，并把任务推进到计算。

## 样例 2：概率中的“至少”，误读成“恰好”

### 输入与约束

- 题目：连续抛掷一枚均匀硬币两次，求至少出现一次正面的概率。
- `task.currentStudentText`：「可能是正正、正反、反正、反反。我只选正反和反正，因为至少一次就是只有一次。」
- `latestEvaluation`：`WRONG + INCOMPLETE`；四个等可能结果已列出，对“至少一次”的理解错误，尚未完成正确的事件筛选和概率计算。
- 已提供历史：无。
- 当前目标：澄清“至少”的数量范围。
- `allowedAction`：`CORRECT_AND_ASK`。
- `doNotRepeat`：不重复要求列举四种结果；`doNotReveal`：不提供应选的结果集合、结果个数或最终概率；`responseGoal`：让学生解释限定词。

### 判断依据

优先假设为“题意理解问题”。错误证据来自学生对限定词的明确解释，无需先追溯概率公式或独立事件知识。

### 推荐输出

```json
{
  "content": "你已经列出了四种结果；其中“至少一次就是只有一次”把“至少”与“恰好”的含义混在了一起。",
  "questions": [
    {
      "id": "meaning_02",
      "question": "请用自己的话说明题目中“至少出现一次正面”对出现次数的要求。"
    }
  ]
}
```

### 后续观察与质量标准

- 若说“一次或更多”，支持限定词含义已澄清；后续还需由学生把该含义用于筛选结果。
- 若重复“只有一次”，保持对题意理解的关注，不把它扩大为概率能力不足。
- 不合格写法：“正正也满足条件，对吗？”既泄露应选结果，又只要求附和。

## 样例 3：行程题中，“到达时间”与“行驶时间”混淆

### 输入与约束

- 题目：客车8:20出发，路程180千米，平均速度60千米/时，中途不停。求到达时刻。
- `task.currentStudentText`：「180除以60，算出3小时。」
- `latestEvaluation`：`CORRECT + INCOMPLETE`；行驶时长计算正确，尚未回答到达时刻。
- 已提供历史：此前学生说“题目问到达时间，我理解成在路上用了多久”；已有反馈“你求得的是行驶时长”，但后续自讲仍止于3小时。后端已按无进展规则给定提示动作。
- 当前目标：辨认最终要回答的时间类型。
- `allowedAction`：`GIVE_HINT`。
- `doNotRepeat`：不重发“你求得的是行驶时长”；`doNotReveal`：不提供到达时刻；`responseGoal`：借助钟面定位所求对象。

### 判断依据

优先假设为“题意理解问题”。当前文本单独看也可能只是未讲完，但已提供历史明确显示对“到达时刻”的误读，因此无需重新验证除法或速度公式。

### 推荐输出

```json
{
  "content": "题目最后要填写的是钟面上的读数。把8:20标作起点，用已经算出的3小时沿时间线向后推进，再记录终点的钟面读数。",
  "questions": []
}
```

### 后续观察与质量标准

- 后续能回答11:20，说明在提示帮助下将时长转换为时刻；不能据此认定学生最初就读懂了所求对象。
- 若理解要填钟面读数但跨小时计算出错，应根据新证据转向执行或时间知识问题。
- 不合格写法：“你到底会不会算时间？”将局部条件理解扩大为泛化能力评价。

## 合理性批判与不足

1. 重述题意能暴露误读，但语言表达较弱的学生也可能复述不清；应允许使用关系式或简短说明，避免将表达困难误判为题意困难。
2. 第三例依赖历史才足以优先考虑题意问题。历史缺失时应保留其他候选原因，不能只见未给最终答案就判定误读。
