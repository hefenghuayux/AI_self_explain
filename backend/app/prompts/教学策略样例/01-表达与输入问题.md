# 表达与输入问题：三个经典样例

## 使用说明

依据 `backend/app/prompts/generate_teaching.md` 当前版本编写。六个文件按六类原因组织，不代表新增六种后端动作。本文是人工审阅用的教学样例，场景和学生话语均为构造材料；输入采用摘要，不能直接作为完整 TeachingContext 请求。

每例的 JSON 是本轮学生可见输出，只有 `content` 和 `questions`；其余分析和观察标准仅供编写、评审使用。动作已由后端给定，分类不改变动作、计数或状态。所有示例均假定尚未触发解析展示阈值。

本模块优先验证学生能否补足表达。未写出依据、符号不清、缺少单位可能影响评价，但单次遗漏不能证明知识缺失，也不能断言由语音识别造成。

## 样例 1：三角形内角计算正确，依据没有讲出

### 输入与约束

- 题目：三角形 ABC 中，∠A＝48°、∠B＝67°，求 ∠C，并说明依据。
- `task.currentStudentText`：「我用180减48再减67，得到65度。」
- `latestEvaluation`：`CORRECT + INCOMPLETE`；已覆盖列式和计算，缺失“说明三角形内角和为180°”。没有已确认的错误。
- 已提供历史：无。
- 当前目标：补充式子中180°的依据。
- `allowedAction`：`ASK_FOCUSED_QUESTION`。
- `doNotRepeat`：无；`doNotReveal`：不提前说出内角和定理；`responseGoal`：验证学生能否独立补充依据。

### 判断依据

优先假设为“表达与输入问题”，候选为“知识应用问题”。正确的计算支持学生掌握了操作，但不能证明其理解180°的来源。只追问这一个依据，无需退回讲授角的定义。

### 推荐输出

```json
{
  "content": "“我用180减48再减67”已经把求角的算式写出来了，还需要补上其中一个数的依据。",
  "questions": [
    {
      "id": "expression_01",
      "question": "你这一步使用的180°是根据什么确定的？"
    }
  ]
}
```

### 后续观察与质量标准

- 若学生自行说明三角形三个内角之和为180°，支持本次只是遗漏依据；仍由后续评价决定评分点是否覆盖。
- 若只说“这类题都减180”或“老师教的”，证据不足以证明理解，可重新考虑知识理解或应用问题。
- 不合格写法：“三角形内角和是180°，所以你用了什么定理？”问题已被前文回答，失去验证价值。

## 样例 2：分式输入缺少括号，先确认表达范围

### 输入与约束

- 题目：把“x与3的和的一半等于5”列成方程，再求 x。
- `task.currentStudentText`：「我先把x和3相加，再把这个和除以2。我输入的是x+3/2=5。」
- `latestEvaluation`：`WRONG + INCOMPLETE`；文字正确说明运算顺序，但“x+3/2=5”未表达整项除以2；求解步骤尚未覆盖。
- 已提供历史：无；没有原始录音、输入设备或转写错误的证据。
- 当前目标：使符号式准确反映学生已经说出的运算顺序。
- `allowedAction`：`CORRECT_AND_ASK`。
- `doNotRepeat`：无；`doNotReveal`：不直接提供正确方程或 x 的值；`responseGoal`：指出书写含义后，请学生自行修订。

### 判断依据

优先假设为“表达与输入问题”，候选为“知识理解与回忆问题”。学生已经明确说“这个和除以2”，因此先验证符号表达，比直接判定不懂题意更有依据。仍可能存在对括号或运算优先级的误解。

### 推荐输出

```json
{
  "content": "你说“再把这个和除以2”，但写出的“x+3/2=5”只让3除以2，符号式与这句话的含义不一致。",
  "questions": [
    {
      "id": "expression_02",
      "question": "请重新写出能准确表达你这句话的方程。"
    }
  ]
}
```

### 后续观察与质量标准

- 自行改为 `(x+3)/2=5`，支持其能够修正表达；本轮已经指出范围差异，这属于纠错后的表现，不能作为完全独立掌握的证据。
- 若仍写原式并认为含义相同，需提高对运算优先级或括号知识问题的关注。
- 不合格写法：“你的语音识别漏了括号。”没有输入来源证据，也替学生确定了原因。

## 样例 3：面积单位漏写，用最小提示完成表达

### 输入与约束

- 题目：长方形长8厘米、宽5厘米，求面积并完整表述结果。
- `task.currentStudentText`：「面积用长乘宽，8乘5等于40。」
- `latestEvaluation`：`CORRECT + INCOMPLETE`；已覆盖公式、代入和数值，缺失结果中的面积单位。
- 已提供历史：此前已问“结果中的40表示什么量”，学生答“面积”；随后两次完整自讲仍只写数值，后端已按无进展规则升级为提示。
- 当前目标：补足结果单位，不重讲乘法或面积公式。
- `allowedAction`：`GIVE_HINT`。
- `doNotRepeat`：不再问40是什么量；`doNotReveal`：不直接给出完整答案表述；`responseGoal`：提醒将量与单位一起写出。

### 判断依据

优先假设为“表达与输入问题”，候选为“知识理解与回忆问题”。历史已确认学生知道40指面积，可先提示补齐单位；知道量的名称仍不等于能够正确使用面积单位。

### 推荐输出

```json
{
  "content": "你已说明40表示面积。把结果写成“数值＋对应单位”，让读者能直接看出这个数表示的量。",
  "questions": []
}
```

### 后续观察与质量标准

- 补上“平方厘米”可说明这次提醒有效，不能把提示后补充算作无提示完成。
- 若补成“厘米”，出现了新的单位使用证据，应根据新评价修正原因假设。
- 不合格写法：“单位是什么？再检查一下。”`GIVE_HINT` 不能通过 `content` 偷加诊断问题。

## 合理性批判与不足

1. 三例分别覆盖依据遗漏、符号输入和结果单位，能展示不同表达障碍；但都不能仅凭一次补充排除更深层知识问题。
2. 样例给出了较明确的上下文，真实文本可能同时有多个遗漏。实际使用应只处理当前目标，不能将本文所有追问顺次套用。
