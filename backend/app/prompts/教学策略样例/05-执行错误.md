# 执行错误：三个经典样例

## 使用说明

依据 `backend/app/prompts/generate_teaching.md` 当前版本编写。本文是人工评审用构造样例，输入采用上下文摘要；只有推荐 JSON 面向学生。动作由后端给定，均未触发解析展示阈值。

只有思路和依据基本正确且存在局部操作证据时，才优先考虑执行错误。三个场景分别是符号操作、单位换算中的算术、代入时抄错数据；均不把单次失误解释为“粗心”“注意力差”或稳定能力特征。

## 样例 1：知道去括号规则，负数乘法局部失误

### 输入与约束

- 题目：化简 `−(2x−3)＋4x`，说明去括号和合并同类项的步骤。
- `task.currentStudentText`：「括号前的负号相当于乘负1，括号里的每一项都乘负1。我写成−2x−3＋4x，后面还没合并。」
- `latestEvaluation`：`WRONG + INCOMPLETE`；已说明分配规则，但常数项符号操作错误，尚未完成合并步骤。
- 已提供历史：最近一次回答中，学生独立算对了 `(-1)×(-5)`，并说明两个负数相乘得正数。
- 当前目标：检查常数项的局部乘法。
- `allowedAction`：`CORRECT_AND_ASK`。
- `doNotRepeat`：不重问去括号的一般规则；`doNotReveal`：不提供本次乘法结果、完整去括号式或最终化简式；`responseGoal`：定位已经确认的错误，让学生重算该局部。

### 判断依据

优先假设为“执行错误”。当前说出的规则和历史基础运算证据相互支持，书写结果却与之不一致。若学生无法重算，应允许修正为知识理解与回忆问题。

### 推荐输出

```json
{
  "content": "你说“括号里的每一项都乘负1”，这个依据是对的；写成“−2x−3＋4x”时，常数项的符号处理出了错。先只核对这一项。",
  "questions": [
    {
      "id": "execution_01",
      "question": "按你刚才说明的规则，(-1)×(-3)应算得多少？"
    }
  ]
}
```

### 后续观察与质量标准

- 自行算出3并修订原式，支持这次存在局部执行失误；因错误位置已被指出，这属于定向核对后的纠正。
- 若再次说负数乘负数得负数，应重新核查符号知识，不能继续笼统要求“认真检查”。
- 不合格写法：“负负得正，所以答案是多少？”先交出要验证的符号依据，降低了重算的诊断价值。

## 样例 2：换算关系正确，除法结果差一位

### 输入与约束

- 题目：小车以18千米/时匀速行驶4秒，求这段时间的路程，并解释单位处理。
- `task.currentStudentText`：「先换成米每秒，18千米是18000米，1小时是3600秒。18000除以3600等于50，接下来用这个速度乘4秒得到路程。」
- `latestEvaluation`：`WRONG + COMPLETE`；已涉及单位换算、速度计算和路程计算方法，但除法中间结果错误，影响后续代入。
- 已提供历史：无。
- 当前目标：修正单位换算中的局部除法。
- `allowedAction`：`GIVE_CORRECTION`。
- `doNotRepeat`：无；`doNotReveal`：不计算4秒的路程，不提供整题最终答案；`responseGoal`：说明算术错误并给出可核对的局部依据。

### 判断依据

优先假设为“执行错误”。学生把千米到米、小时到秒的关系与除法方向均说对，已有证据将错误定位到除法结果。不能只见单位换算出错就整段重讲单位制。

### 推荐输出

```json
{
  "content": "“18千米是18000米，1小时是3600秒”的换算依据正确。错误在“18000除以3600等于50”：这一商应为5，因为3600×5＝18000，所以当前速度是5米/秒。把修正后的速度用于你已经说明的路程计算步骤。",
  "questions": []
}
```

### 后续观察与质量标准

- 使用修正后的速度继续计算，说明能够承接本轮纠正；不能算作自行发现除法错误。
- 若后续又混用千米和秒，应根据新证据检查单位关系，不把后续问题全部归为算术失误。
- 不合格写法：“最后路程是20米。”本轮只修正中间换算，最终路程留给学生完成。

## 样例 3：代入顺序正确，却把已知数抄错

### 输入与约束

- 题目：一次函数 `y＝2x＋3`，求 `x＝−2` 时的函数值，再判断对应点是否在x轴上。
- `task.currentStudentText`：「把给定的x代入，先乘2再加3。我写y=2×2+3，后面的点的位置还没判断。」
- `latestEvaluation`：`WRONG + INCOMPLETE`；代入计算顺序正确，但将给定的−2写为2，函数值和位置判断尚未正确完成。
- 已提供历史：此前学生已读出“x取负2”，并独立解释过负数代入时保留数值的符号。
- 当前目标：核对代入式与题干数值的一致性。
- `allowedAction`：`CORRECT_AND_ASK`。
- `doNotRepeat`：不重问一次函数的定义或代入顺序；`doNotReveal`：不提供正确代入式、函数值或点的位置；`responseGoal`：让学生自行定位抄写差异。

### 判断依据

优先假设为“执行错误”，候选为“表达与输入问题”。已有历史支持学生知道给定数是负数，但当前文本不足以确定遗漏发生于抄写、输入还是操作过程，因此不声称已经找到具体成因。

### 推荐输出

```json
{
  "content": "你说明的代入顺序正确，但“y=2×2+3”代入的数值与题干给定的x不一致。先核对数值，再继续运算。",
  "questions": [
    {
      "id": "execution_03",
      "question": "对照题干，你的代入式中哪一处需要修改？"
    }
  ]
}
```

### 后续观察与质量标准

- 指出代入值漏了负号，并自行修订，支持已定位局部不一致；不据此评价学生是否“认真”。
- 若表示“代入时负号本来就要去掉”，出现规则误解的新证据，应修正假设。
- 不合格写法：“把第二个2改成−2，哪里写错了？”在问题前已经替学生完成了核对。

## 合理性批判与不足

1. 正确说出规则不保证每次都理解透彻；历史证据也可能来自提示。三例需要结合证据来源使用，不能看到“一步算错”就固定分类。
2. 定向核对能快速推进当前题目，但无法单独证明学生具备独立发现错误的能力；本轮成功纠正不应被夸大为已经建立稳定检查习惯。
