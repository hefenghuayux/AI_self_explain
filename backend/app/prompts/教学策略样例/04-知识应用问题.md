# 知识应用问题：三个经典样例

## 使用说明

依据 `backend/app/prompts/generate_teaching.md` 当前版本编写。本文为人工审阅用构造样例，输入是上下文摘要；JSON 才是学生可见输出。动作由后端给定，均未触发解析展示阈值。

本模块的共同前提是：已有证据支持学生理解相关题意和知识，却尚未把它们用于当前目标。不按“起步、连接、组合、排序”建立额外原因类别。三例分别考察数量建模、几何对应、总量组织，避免只换数字重复同一种卡点。

## 样例 1：年龄问题，会写倍数，不会表示若干年后的年龄

### 输入与约束

- 题目：父亲今年年龄是女儿的4倍，5年后父亲年龄是女儿的3倍，求女儿今年的年龄。
- `task.currentStudentText`：「设女儿今年x岁，父亲今年4x岁。5年后两个人都大5岁，到那时父亲是女儿的3倍，但我不知道方程怎么写。」
- `latestEvaluation`：`CORRECT + INCOMPLETE`；已正确设元、表示当前年龄并理解两个条件，缺失5年后年龄的代数表示和关系式。
- 已提供历史：学生曾独立说明“某人的年龄是y岁，过2年就是y+2岁”，未收到本题列式提示。
- 当前目标：将时间条件应用到女儿的年龄表达式。
- `allowedAction`：`ASK_FOCUSED_QUESTION`。
- `doNotRepeat`：不重新验证一般的年龄增长含义；`doNotReveal`：不提供5年后的年龄表达式、方程或最终年龄；`responseGoal`：观察学生能否将已懂的关系用于本题。

### 判断依据

优先假设为“知识应用问题”。学生已经正确复述条件，也有独立解释年龄增长的历史证据，当前应聚焦本题变量与时间条件的联系。

### 推荐输出

```json
{
  "content": "“设女儿今年x岁，父亲今年4x岁”已经明确了今年的年龄关系。接着只处理女儿在题目另一个时间点的年龄。",
  "questions": [
    {
      "id": "application_01",
      "question": "按照你设定的x，女儿5年后的年龄应怎样表示？"
    }
  ]
}
```

### 后续观察与质量标准

- 自行写出 `x+5`，说明完成了当前转换；仍未证明能同时组织父亲年龄和三倍关系。
- 若写成 `5x`，出现对时间增长或代数表示的新疑点，应重新考虑知识理解，不能固守原分类。
- 不合格写法：“方程是4x+5=3(x+5)，你能解吗？”直接完成了待帮助建立的数量关系。

## 样例 2：相似三角形，知道比例性质却找不到对应边

### 输入与约束

- 题目：在三角形 ABC 中，D在AB上，E在AC上，DE∥BC。已知AD＝3、DB＝2、AE＝4，求EC。
- `task.currentStudentText`：「DE平行BC，可以得到△ADE与△ABC相似。对应边成比例，但我不知道AD应该和哪条边对应。」
- `latestEvaluation`：`CORRECT + INCOMPLETE`；已覆盖平行条件、相似判断和性质表述，缺失对应边关系与后续计算。
- 已提供历史：学生已经独立指出两三角形中“A对应A，D对应B，E对应C”，并解释对应边的端点应是对应顶点；尚未写出本题边的对应关系。
- 当前目标：把顶点对应关系落实到边AD。
- `allowedAction`：`ASK_FOCUSED_QUESTION`。
- `doNotRepeat`：不再询问三个顶点各对应谁；`doNotReveal`：不提供对应边、比例式或EC的长度；`responseGoal`：验证已知对应关系能否用于当前边。

### 判断依据

优先假设为“知识应用问题”，候选为“表达与输入问题”。已有历史支持相关知识理解，当前缺口是能否把知识落实到具体图形；也可能只是学生尚未组织好表达。

### 推荐输出

```json
{
  "content": "你已经确定了两组三角形的顶点对应关系，可以沿用这份对应关系处理当前这一条边。",
  "questions": [
    {
      "id": "application_02",
      "question": "根据你已经确定的顶点对应关系，AD在△ABC中对应哪条边？"
    }
  ]
}
```

### 后续观察与质量标准

- 回答AB，并能在后续自讲中沿端点对应解释，支持知识已用于当前图形；本轮不同时要求写比例和计算。
- 若仍只背“对应边成比例”，只能证明规则被复述，不能证明找到对应边。
- 不合格写法：“AD对应AB，所以AE对应谁，比例怎么列，EC是多少？”泄露本轮答案，并拼接多个独立任务。

## 样例 3：往返平均速度，知道定义却不会组织总路程和总时间

### 输入与约束

- 题目：某人往返相距60千米的两地，去程速度30千米/时，返程速度20千米/时，途中不停。求全程平均速度。
- `task.currentStudentText`：「平均速度是总路程除以总时间。去的时候每小时30千米，回来每小时20千米，两段都是60千米，但我不知道总时间该怎样放进式子。」
- `latestEvaluation`：`CORRECT + INCOMPLETE`；定义和题意正确，尚未组织两段时间并完成计算。
- 已提供历史：学生独立解释过“同一路程，速度慢会用更多时间”和“时间由路程除以速度得到”；此前已问“全程时间由哪些部分组成”，学生答“去和回”，后续自讲未新增计算步骤，后端按无进展规则给定提示。
- 当前目标：将单段时间关系用于两段不同速度的路程。
- `allowedAction`：`GIVE_HINT`。
- `doNotRepeat`：不再问总时间由几段组成，不重讲平均速度定义；`doNotReveal`：不提供各段时间、总时间、完整代入式或最终平均速度；`responseGoal`：给出组织条件的最小操作提示。

### 判断依据

优先假设为“知识应用问题”。学生已能说明定义和单段关系，卡点在于把两个过程组织进同一计算，而非不知道平均速度概念。

### 推荐输出

```json
{
  "content": "把去程和返程分别写成一行，每行只放本段的路程与速度，并由这一对数据求本段时间。两段时间算出后，再合成你需要的全程时间。",
  "questions": []
}
```

### 后续观察与质量标准

- 学生自行得到去程2小时、返程3小时，可支持这一提示帮助完成分段计算；继续得到全程平均速度24千米/时，仍属于受支持后的完成。
- 若改用两个速度直接平均，应结合其解释重新检查平均速度含义，不能因历史正确就忽略当前冲突。
- 不合格写法：直接给出 `120÷(60÷30＋60÷20)`，让学生只做计算。核心的总量组织已经被代做。

## 合理性批判与不足

1. 应用问题的判断依赖已有知识证据。真实历史若只有背公式，应降低分类把握，不能套用本文对知识理解程度的判断。
2. 把任务拆到一个局部能减少负担，但完成局部不代表能独立整合全部解法；后续完整自讲仍有必要，本文不据此提前判定完成。
