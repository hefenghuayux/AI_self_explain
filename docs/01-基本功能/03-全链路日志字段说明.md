# 全链路日志字段说明

## 1. 文档目的

前端“查看全链路”页面保持简洁，直接展示后端返回的英文 JSON，不在页面中为每个字段重复增加中文注释。

本说明文档集中解释统一审计日志中的字段、常见取值和阅读方法。排查日志时，可以一边查看前端 JSON，一边对照本文档。

统一审计接口：

```text
GET /api/sessions/{session_id}/audit/trace
```

会话导出文件：

```text
output/audit/sessions/{session_id}/trace.jsonl
output/audit/sessions/{session_id}/audit.md
```

## 2. 完整示例

下面是一条 AI 外部调用完成事件：

```json
{
  "schemaVersion": "2.0",
  "eventId": "external-call-18",
  "sequence": 5,
  "occurredAt": "2026-08-10T10:20:30.842Z",
  "eventName": "ai.call.completed",
  "severity": "INFO",
  "source": {
    "service": "ai-self-explain-backend",
    "module": "audit_trace"
  },
  "correlation": {
    "sessionId": 42,
    "requestId": "req-text-001"
  },
  "operation": {
    "name": "AI_EVALUATION",
    "kind": "EXTERNAL_CALL",
    "attemptNumber": 1
  },
  "result": {
    "status": "SUCCESS",
    "durationMs": 842,
    "errorType": null,
    "errorMessage": null
  },
  "data": {
    "provider": "test-ai",
    "model": "test-ai-model",
    "rawResponse": {
      "characterCount": 378,
      "sha256": "..."
    }
  },
  "references": {
    "externalCallRecordId": 18
  },
  "privacy": {
    "redactedFields": [
      "rawResponse"
    ]
  }
}
```

这条日志表示：会话 `42` 在请求 `req-text-001` 中完成了一次 AI 评价调用；这是第一次调用，模型耗时 `842` 毫秒并成功返回。完整模型原始响应没有直接写入日志，只保留字符数量、SHA-256 和数据库记录编号。

## 3. 顶层字段

| 字段 | 作用 | 示例 |
| --- | --- | --- |
| `schemaVersion` | 统一日志数据契约版本。`2.0` 删除了未形成实际链路关系的跨度字段。 | `2.0` |
| `eventId` | 当前事件的唯一编号，用于去重、定位和关联原始数据库记录。 | `external-call-18` |
| `sequence` | 当前事件在整个会话审计链路中的排序序号。 | `5` |
| `occurredAt` | 事件实际发生时间，使用 ISO 8601 格式。 | `2026-08-10T10:20:30.842Z` |
| `eventName` | 事件类型，说明系统发生了什么。 | `ai.call.completed` |
| `severity` | 日志严重级别。 | `INFO`、`WARNING`、`ERROR` |
| `source` | 产生事件的服务和模块。 | `ai-self-explain-backend` |
| `correlation` | 关联学习会话和请求的标识。 | 见下文 |
| `operation` | 当前执行的业务操作和操作类别。 | 见下文 |
| `result` | 当前操作的成功、失败、耗时和错误信息。 | 见下文 |
| `data` | 与当前事件类型有关的业务数据。不同事件的字段不同。 | 见下文 |
| `references` | 关联数据库记录的编号，不复制完整原始记录。 | 见下文 |
| `privacy` | 说明哪些敏感字段已经脱敏。 | 见下文 |

## 4. source：事件来源

| 字段 | 作用 |
| --- | --- |
| `source.service` | 产生当前事件的应用或服务名称。 |
| `source.module` | 负责聚合或生成当前事件的代码模块。 |

当前统一审计事件由后端 `audit_trace` 模块聚合，因此常见值是：

```json
{
  "service": "ai-self-explain-backend",
  "module": "audit_trace"
}
```

## 5. correlation：链路关联标识

| 字段 | 作用 |
| --- | --- |
| `sessionId` | 学习会话编号。一次完整自讲会话中的多次请求共用同一个 `sessionId`。 |
| `requestId` | 一次 HTTP 或 WebSocket 请求编号，用于在应用日志和数据库审计记录之间定位同一次请求。 |

统一审计 JSON 只保留当前实际使用的会话和请求关联字段。内部运行日志仍可通过 `application.log` 查看更细的运行上下文。

```text
sessionId
  ├── requestId：提交一次自讲
  └── requestId：请求一次提示
```

部分没有请求编号的记录只保留：

```text
requestId: null
```

## 6. operation：操作信息

| 字段 | 作用 |
| --- | --- |
| `operation.name` | 业务代码中的操作名称，例如 `AI_EVALUATION`、`SUBMIT_TEXT`。 |
| `operation.kind` | 操作类别，例如 `EXTERNAL_CALL`、`STATE_TRANSITION`、`STUDENT_INPUT`。 |
| `operation.attemptNumber` | 外部服务调用次数。第一次调用为 `1`，发生重试后依次增加。 |

常见 `kind`：

| 值 | 含义 |
| --- | --- |
| `STATE_TRANSITION` | 确定性业务状态转换。 |
| `EXTERNAL_CALL` | AI 或 ASR 外部服务调用。 |
| `STUDENT_INPUT` | 学生输入保存。 |
| `AI_EVALUATION` | AI 评价结果处理。 |
| `FILE_STORAGE` | 音频或其他文件保存。 |

## 7. result：执行结果

| 字段 | 作用 |
| --- | --- |
| `result.status` | 当前操作结果，通常是 `SUCCESS` 或 `ERROR`。 |
| `result.durationMs` | 当前操作耗时，单位为毫秒；不适用时为 `null`。 |
| `result.errorType` | 后端定义的错误分类；成功时通常为 `null`。 |
| `result.errorMessage` | 具体错误信息；成功时通常为 `null`。 |

常见错误类型：

```text
ASR_TIMEOUT
ASR_SERVICE_ERROR
AI_TIMEOUT
AI_SERVICE_ERROR
AI_SCHEMA_ERROR
AI_RELATION_ERROR
FILE_STORAGE_ERROR
ILLEGAL_STATE_TRANSITION
```

## 8. data：事件业务数据

`data` 的内容由 `eventName` 决定，不同事件不会拥有完全相同的字段。

### 8.1 状态转换事件

适用事件：

```text
session.created
state.transitioned
```

| 字段 | 作用 |
| --- | --- |
| `fromStatus` | 转换前的会话业务状态。 |
| `toStatus` | 转换后的会话业务状态。 |
| `fromFlowStage` | 转换前的教学流程阶段。 |
| `toFlowStage` | 转换后的教学流程阶段。 |
| `beforeSnapshot` | 转换前的状态、轮次、计数器和评分点快照。 |
| `afterSnapshot` | 转换后的状态、轮次、计数器和评分点快照。 |

### 8.2 AI 或 ASR 外部调用

适用事件：

```text
ai.call.completed
ai.call.failed
asr.call.completed
asr.call.failed
```

| 字段 | 作用 |
| --- | --- |
| `provider` | 实际调用的 AI 或 ASR 服务提供商。 |
| `model` | 实际调用的模型名称。 |
| `rawResponse.characterCount` | 外部服务原始响应字符数量。 |
| `rawResponse.sha256` | 外部服务原始响应的 SHA-256。完整原文不直接写入导出日志。 |

### 8.3 学生输入和语音采集

适用事件：

```text
student.input.submitted
student.input.confirmed
voice.capture.completed
```

| 字段 | 作用 |
| --- | --- |
| `round` | 当前自讲轮次。 |
| `voiceTarget` | 语音输入目标，例如自讲、疑问或子问题回答。 |
| `voiceTargetId` | 语音目标的具体编号，例如引导问题编号。 |
| `content` | 学生提交内容的字符数量和 SHA-256。 |
| `asrTranscript` | ASR 转写结果的字符数量和 SHA-256。 |
| `confirmedText` | 学生最终确认文本的字符数量和 SHA-256。 |
| `confirmedAt` | 学生确认文本的时间。 |
| `context` | 输入对应的轮次、输入模式和尝试编号等上下文。 |

### 8.4 AI 评价校验

适用事件：

```text
ai.output.validated
ai.output.validation_failed
```

| 字段 | 作用 |
| --- | --- |
| `correctness` | AI 对答案正确性的判断。 |
| `completeness` | AI 对答案完整性的判断。 |
| `coveredPoints` | 学生已经覆盖的评分点。 |
| `missingPoints` | 学生仍未覆盖的评分点。 |
| `errorEvidence` | AI 指出的错误证据。 |
| `feedback` | 生成给学生的评价反馈。 |
| `confidence` | 模型对当前判断的置信度。 |
| `nextAction` | AI 建议的下一步动作；最终业务转换仍由后端确定性规则执行。 |
| `needHumanReason` | 需要人工处理时的原因。 |
| `promptVersion` | 本次调用使用的提示词版本。 |
| `validationStatus` | AI 返回结构是否通过后端校验。 |
| `rawResponse` | 模型原始响应的字符数量和 SHA-256。 |

### 8.5 教学支持事件

适用事件：

```text
support.generated
```

| 字段 | 作用 |
| --- | --- |
| `round` | 当前教学轮次。 |
| `status` | 教学支持记录是否有效。 |
| `content` | 实际发送给学生的教学支持内容。 |
| `guidedQuestions` | 生成的引导问题。 |
| `guidedAnswers` | 学生对引导问题的回答。 |
| `followUpContent` | 对引导问题回答的后续反馈。 |
| `mainDraft` | 学生主要草稿的字符数量和 SHA-256。 |
| `doubtText` | 学生疑问文本的字符数量和 SHA-256。 |

### 8.6 音频保存事件

适用事件：

```text
audio.persisted
```

| 字段 | 作用 |
| --- | --- |
| `contentType` | 音频文件类型。 |
| `sizeBytes` | 音频文件大小，单位为字节。 |
| `sha256` | 音频内容的 SHA-256。 |

## 9. references：数据库记录引用

| 字段 | 作用 |
| --- | --- |
| `stateTransitionEventId` | 对应 `state_transition_events` 记录编号。 |
| `externalCallRecordId` | 对应 `external_call_records` 记录编号。 |
| `attemptId` | 对应 `explanation_attempts` 记录编号。 |
| `evaluationId` | 对应 `ai_evaluations` 记录编号。 |
| `studentSubmissionId` | 对应 `student_submissions` 记录编号。 |
| `supportEventId` | 对应 `support_events` 记录编号。 |
| `audioFileId` | 对应 `audio_files` 记录编号。 |

这些字段用于定位权威数据库记录。统一 JSON 和 Markdown 是审计投影，不替代原始数据库记录。

## 10. privacy：脱敏信息

| 字段 | 作用 |
| --- | --- |
| `redactedFields` | 列出没有直接写入统一日志的敏感字段。 |

例如：

```json
{
  "redactedFields": [
    "rawResponse"
  ]
}
```

表示完整外部响应没有直接写入当前事件，只保存摘要和数据库引用。

## 11. 常见 eventName

| eventName | 含义 |
| --- | --- |
| `session.created` | 会话创建。 |
| `state.transitioned` | 业务状态或教学流程阶段发生变化。 |
| `student.input.submitted` | 学生输入已经保存。 |
| `student.input.confirmed` | 学生文本输入已经确认。 |
| `voice.capture.completed` | 语音采集已经完成。 |
| `asr.call.completed` | ASR 调用成功。 |
| `asr.call.failed` | ASR 调用失败。 |
| `ai.call.completed` | AI 外部调用成功。 |
| `ai.call.failed` | AI 外部调用失败。 |
| `ai.output.validated` | AI 结构化输出通过后端校验。 |
| `ai.output.validation_failed` | AI 结构化输出未通过后端校验。 |
| `support.generated` | 教学支持已经生成并保存。 |
| `audio.persisted` | 音频文件已经保存。 |

## 12. 推荐阅读顺序

排查一条事件时，建议按以下顺序阅读：

1. 看 `sequence` 和 `occurredAt`，确认事件顺序和发生时间。
2. 看 `eventName`，确认系统发生了什么。
3. 看 `result`，确认成功、失败、耗时和错误原因。
4. 看 `correlation`，确认属于哪个会话和请求。
5. 看 `operation`，确认业务操作和重试次数。
6. 看 `data`，确认当前事件的业务结果。
7. 看 `references`，需要时定位数据库原始记录。
8. 看 `privacy`，确认哪些内容已经脱敏。

## 13. 合理性批判与不足

1. 固定说明文档能保持前端简洁，但日志 Schema 增加字段时必须同步更新本文档，否则说明会落后于实现。
2. `data` 是事件相关结构，不可能用一张完全固定的字段表覆盖所有未来事件；新增事件类型时需要补充对应小节。
3. 当前统一审计 JSON 不包含内部跨度字段；如果未来需要生成真正的链路树，应单独设计稳定的 span 标识和父子关系，而不是复用事件编号。
4. JSON 中保留英文枚举便于搜索和程序处理，但非技术用户仍需要对照本文档阅读。
