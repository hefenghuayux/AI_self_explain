# 错因驱动引导实施方案

编写日期：2026-09-15

## 目标

模型根据学生当前表达、评价结果和已有教学历史，判断当前卡点的一个主要原因，并据此生成局部引导。原因只描述本轮可修正的假设，不代表学生的长期能力。

## 原因分类

`main_reason` 只能填写以下六个值之一。`other_reasons` 是可能或次要原因数组，没有时为空数组：

| 值 | 使用条件 | 引导方向 |
| --- | --- | --- |
| 表达与输入问题 | 思路基本正确，但表达遗漏、过短或文本含义不清 | 请学生补充、列式或改写原意 |
| 题意理解问题 | 误解或遗漏条件，不清楚对象或要求 | 请学生复述相关条件和所求 |
| 知识理解与回忆问题 | 不知道、想不起或误解概念、公式、规则 | 核对最小必要概念及适用条件 |
| 知识应用问题 | 知道相关知识，但不会对应到当前题目或解释依据 | 检查条件与知识之间的对应关系 |
| 执行错误 | 计算、抄写、代入或符号操作出错 | 让学生局部重算或核对 |
| 原因未明 | 信息不足、证据冲突或候选原因无法区分 | 提出最小澄清问题，暂缓归因 |

选择依据仅限模型实际收到的学生原文、评价结果、当前目标和教学历史。一次错误不能推出“粗心”“基础差”等稳定特征。原因不确定时使用“原因未明”。

## 输出契约

实际合并响应必须包含：

```json
{
  "main_reason": "原因分类中的一个值",
  "other_reasons": [],
  "judge_reason": "简短的原因判断理由",
  "content": "教学内容或 null",
  "questions": []
}
```

`main_reason`、`other_reasons` 和 `judge_reason` 必填。问题只能针对 `main_reason`，不能针对 `other_reasons` 分别提问。终态和 `UNCERTAIN` 也要填写这些字段，但 `content` 必须为 `null`、`questions` 必须为空数组。追问动作仍按当前 schema 的数量规则返回问题；原因不会改变状态、计数、阈值或动作校验。

## 内容规则

1. 先定位一个当前卡点，再选择原因；不要为区分原因额外追问。
2. 问题应验证一个关键疑点，简短、开放且不暗示答案。
3. 提示和纠错只处理当前局部，不直接给出完整解析或后续评分点答案。
4. `judge_reason` 只写一小段判断依据；`main_reason` 和 `other_reasons` 不得写成长篇分析。

## 当前接入位置

- `backend/app/prompts/evaluate_explanation.md`：当前实际的评价与教学合并入口。
- `backend/app/prompts/generate_teaching.md`：教学提示词参考入口，同步使用相同的原因字段契约。
- `backend/app/schemas/merged.py`：校验原因字段和 `judge_reason`；状态和问题关系继续由现有确定性代码控制。

## 验收

- 模型响应始终包含非空 `main_reason`、`judge_reason` 和 `other_reasons` 数组。
- 原因字段只使用六个允许值，未知值或缺失值由 schema 拒绝。
- 原有教学动作、状态转换、支持计数和问题数量规则保持不变。
- 通过现有后端 schema 与教学决策测试，并检查请求提示词和 Git diff。

## 合理性批判

原因字段便于审阅每轮引导，但它仍是模型判断，不能单独作为学生画像或学习效果证据。若后续样本显示原因分类经常不稳定，应评估只记录“当前卡点”的简化方案，避免把不可靠标签带入状态和计数逻辑。
