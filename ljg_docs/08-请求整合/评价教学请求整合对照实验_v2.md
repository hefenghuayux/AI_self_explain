## 实验概要

三个对照实验，比较 `evaluate_explanation` 与 `generate_teaching` 在不同字段拆分粒度下的效果与耗时。每组实验跑 3 个不同学生回答（共 9 组流程，含 15 次模型调用）。

| 实验  | 结构                               | 输出字段                                                                                                   |
| ----- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 实验1 | 两次调用：① eval → ② teach      | ① correctness, completeness, hasProgress；② main_reason, other_reasons, judge_reason, content, questions |
| 实验2 | 两次调用：① eval+原因 → ② teach | ① correctness, completeness, hasProgress, main_reason, other_reasons, judge_reason；② content, questions |
| 实验3 | 一次合并调用                       | correctness, completeness, hasProgress, main_reason, other_reasons, judge_reason, content, questions       |

## 题目与学生

### 题目材料（题库 question id=3）

> （高一数学·二次函数，中等）已知函数 f(x)=x²−2ax+2a−1（a∈R）。
> 当 x∈[0,2] 时，f(x) 的最大值为 3。求实数 a 的所有可能取值，
> 并求每种情况下 f(x) 在区间 [0,2] 上的最小值。

评分点（rubricPoints）：

1. 指出二次函数图像开口向上，因此区间 [0,2] 上的最大值必在端点 x=0 或 x=2 处取得
2. 正确计算 f(0)=2a−1，f(2)=3−2a，并建立 max{2a−1, 3−2a}=3
3. 分类讨论两个端点取得最大值的情形并校验另一端点不超过 3，得到 a=0 或 a=2
4. 分别代入 a=0 和 a=2，结合函数图像或配方法求出区间最小值均为 −1，并说明对应取值点

完整上下文包含：standardAnswer、commonErrors(4条)、alternativeSolutions(2条)、layeredHints(4条)、guidedQuestions(3条)、fullSolution（完整解析）。

### 三组学生回答

| 编号        | 说明                      | 学生自讲文本                                                                                                                                                                          |
| ----------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A** | 有进展、正确不完整        | 这题二次函数开口向上，因为 x² 系数是 1 大于 0。闭区间 [0,2] 上的最大值应该在端点 x=0 或 x=2 取到。先算 f(0)=2a−1，f(2)=3−2a，然后令 f(0)=3 得 a=2，这时候 f(2)=−1。最大值就是 3。 |
| **B** | 错误理解（最大/最小混淆） | 开口向上，所以最大值在顶点取得。顶点 x=a，f(a)=−a²+2a−1。令最大值等于 3，解出 a。然后最小值也是顶点那里。                                                                          |
| **C** | 无进展表达不清            | 我不知道，感觉就是差不多，不知道最大值怎么算，也不会分类。                                                                                                                            |

## 汇总对比

| 维度                 | 实验1（3+5，两次调用）               | 实验2（6+2，两次调用） | 实验3（8合一，一次调用） |
| -------------------- | ------------------------------------ | ---------------------- | ------------------------ |
| 模型调用次数         | 2                                    | 2                      | **1**              |
| **平均总耗时** | **91.6s**                      | **100.7s**       | **42.7s**          |
| 评价粒度             | correctness/completeness/hasProgress | 同上+原因分类          | 同上+原因分类            |
| 教学粒度             | 原因+内容+问题                       | 只内容+问题            | 原因+内容+问题           |
| 教学内容是否依赖上游 | 依赖3项                              | 依赖6项                | 无外部依赖               |
| 字段一致性           | 需两次串联                           | 需两次串联             | 天然一致                 |
| 容错                 | 两步可独立重试                       | 两步可独立重试         | 整体失败整体重试         |
| 输出预算要求         | 低（每步~1500 tokens）               | 低（每步~1500 tokens） | **高**（需≥4000） |

### 核心发现

1. **合并（实验3）比两步调用快 2 倍以上**：在 `deepseek-v4.1-flash` 推理模型上，单次合并调用 42.7s，远快于实验1（91.6s）和实验2（100.7s）。原因是该模型每次调用都有大量 reasoning overhead（约 60-80% tokens 用于推理），两次调用时 overhead 翻倍。
2. **评价粒度的选择影响教学判断**：实验1A 评价为 `CORRECT+INCOMPLETE`（方向正确判定为正确），实验2A/3A 评价为 `WRONG+INCOMPLETE`（遗漏解判定为错误）。prompt 中不同的评价约束导致判断标准差异。
3. **实验3A 的教学策略偏「纠正」**：合并版未生成追问（`questions=[]`），而实验1A/2A 的教学步都生成了追问。合并时评价+教学共享同一个推理过程，可能削弱了追问的生成。
4. **`needHumanReason` 溢出问题**：当 correctness=UNCERTAIN 时，模型倾向于遵循 prompt 内的规则输出 `needHumanReason`，即使 JSON Schema 不要求。说明 prompt 指令的约束力强于 Schema。
5. **连接稳定性**：9 组流程中 1 组（实验3B）因服务器断开连接而失败，比率~11%。两步方案中每步都是独立的短连接，失败影响面更小。

---

## 结论：能否合并？

**可以合并，且在本模型上合并比两步拆分更快。**

合适合并的场景：

- 使用推理模型（如 `deepseek-v4.1-flash`）— 对推理模型，合并能节省一次完整的推理 overhead，大幅缩短端到端耗时（本实验为 46% 的省时）
- 业务对「评价+教学一次返回」的字段一致性有要求
- 愿意接受更大的 token 预算（max_tokens≥4000）

适合保持两步拆分的场景：

- 使用非推理模型（推理 overhead 小，两步拆分总耗时可能接近合并）
- 需要独立重试容错（教学步失败不影响评价结果）
- 需要确定性规则夹在两步之间修改教学策略
