# 阶段 06：语音录制与 ASR 回填

## 目标

加入语音输入，确保 AI 仍只评价学生通过原有操作最终提交的文本。

## 范围

- 浏览器 PCM 音频采集与本地保存。
- 浏览器到后端、后端到百炼的双向 WebSocket 实时 ASR。
- 原始转写与中间转写展示。
- 学生在录音期间继续使用键盘编辑。
- 转写直接回填到可编辑草稿，学生自行修改。
- ASR 错误记录和恢复。

## 修改内容

- 增加 `AudioFile` 数据模型。
- 使用浏览器 Web Audio API 采集 16 kHz、单声道 PCM，并按配置校验格式、大小和时长。
- 保存音频相对路径、媒体类型、大小和 SHA-256。
- 使用 DashScope SDK 连接百炼 `fun-asr-realtime`，增加双向流式调用记录，并将转写直接回填至相应输入框。
- 分别保存 `asrTranscript` 和 `confirmedText`。

ASR 完成后保持录音开始前的可操作流程阶段：自讲保持 `CAPTURING_INPUT`，疑问/申诉保持 `WAIT_STUDENT_ACTION`，子问题保持 `WAIT_GUIDED_ANSWERS`。学生点击原有提交按钮时才保存最终文本并关联对应语音尝试；不设置 `CONFIRMING_TEXT` 阶段。

实时连接建立失败按配置重试；流中连接中断时不重放已发送 PCM，避免重复转写。失败后退回 `CAPTURING_INPUT`，保留错误记录，允许学生重新录音；不增加支持次数，也不进入 `NEED_HUMAN`。

## 测试要求

- 支持的 PCM 音频可以流式保存。
- 音频格式、大小和时长限制从配置读取。
- 文件写入失败时不创建残缺数据库记录。
- ASR 原始转写和学生最终提交文本分别保存并关联。
- 学生修改后的最终提交文本是 AI 唯一评价输入。
- ASR 连接建立超时和服务异常按配置重试。
- 连接重试耗尽或流中断退回 `CAPTURING_INPUT`。
- ASR 失败不创建评价或支持事件。
- 中间转写不覆盖主输入框，句末转写追加到主输入框。

## 完成标准

- 学生可以实时录音、边编辑边查看转写，随后使用原有提交操作进入现有教学闭环。
- 原始音频、原始转写和确认文本可以关联追溯。
- 本阶段自动测试全部通过。

## 合理性批判与不足

1. 直接回填并由原有提交操作形成最终文本能避免额外状态阻断，但不能证明端到端语音理解准确。
2. 本地音频存储适合单机 Demo，不能直接支持多实例服务。
3. 浏览器实时 PCM 采集依赖 Web Audio API，当前 Demo 支持最新版 Chrome 和 Edge。
