# HG-Bench 论文精读与"AI 自讲 Demo"启发分析

> **论文信息：** HG-Bench: A Benchmark for Multi-Page Handwritten Answer-Region Grounding in Automated Homework Assessment  
> arXiv:2606.25491v1, 清华大学团队  
> 提取日期：2025-07-15

---

## 一、论文背景与解决的问题（约 450 字）

### 背景

自动化作业批改系统正越来越多地用于教育场景，核心流程的第一步就是**空间定位**——系统必须从扫描页面上找到学生写下的每道题答案，以及多步题中的每个步骤区域。下游的 OCR 识别、评分、反馈都依赖这些区域，所以最终评分的天花板被上游定位的精度卡住。

现有评测体系存在三块空白：

1. **自然图像定位基准**（RefCOCO、Flickr30K Entities）只处理"一张图片、一个指代、一个目标"，不涉及文档级的结构化输出。
2. **文档 AI 基准**（DocVQA、ChartQA）只恢复文本内容，不要求空间正确的分层区域输出。就算是 LayoutLM 这类文档理解模型，也只做 OCR 级别的框检测，不管答案和步骤的层级关系。
3. **教育 AI 基准**（MathVista、MathVerse）只管推理——题目的相关区域已经提前切好，模型只需要"看到图然后算答案"，而不是自己去图上找答案在哪。

真实批改场景中最关键的能力——**有序、两级、跨页面感知的手写答案区域定位**——从来没人系统评测过。

### 解决的问题

论文提出了 **HG-Bench**，专门填补这个空缺。它的核心任务是：给一个多页手写作业的图片序列，模型要输出每个题目的完整答案区域（题目级框），对于多步题还要输出按书写顺序排列的步骤级子区域（步骤级框），且步骤框必须严格包含在父题目框内。论文还配套了一个页面感知的评测协议，把"题目定位"和"步骤分解"两个能力解耦开来分别打分——这样就能看清楚模型到底是"大概找到了答案在哪"，还是"真正理清了学生的推理结构"。

## 二、核心内容与方法（约 1100 字）

### 任务定义

输入是 $P$ 页作业图片序列 $\{I_p\}_{p=1}^P$，附带每页的像素尺寸元信息。输出是一个 JSON 数组 $\{q_i\}_{i=1}^N$，每个元素对应一道题，包含：

- `type`：固定为 `complete_answer_box`
- `page_id`：页面索引（1-based）
- `box_2d`：归一化到 [0,1000] 的 xyxy 格式题目级框
- `steps`（可选）：有序步骤列表，每个元素有 `step_id`（按书写顺序从 1 递增）和 `box_2d`

题目级框圈住整道题的完整手写答案，用于逐题给分。步骤级框进一步分解多步推导过程，用于步骤级评分和推理轨迹分析。约束条件：每个步骤框必须完全包含在其父题目框内。坐标默认归一化到 [0,1000]，可反归一化为像素值。

### 数据集构建

从 **1,489,278 张**匿名化学生作业图片起步，经多级自动筛选 + 人工验证，得到 **10,420 个**高质量标注样本。来源分两个渠道：

- **企业渠道**（6,765 样本）：正式答题卡标准化考试扫描，多页、多步题占比高，布局规整
- **消费渠道**（3,655 样本）：家长或学生用手机拍照上传，单页为主，题型分布更均匀，包含更多真实世界的拍摄变化（手影、透视畸变、行间距不规则等）

在标注后按四个轴——学科、年级、每样本页数、答案类型——做分层采样，分出 **500 样本做测试集（HG-Bench）** 和 **9,920 样本做训练集（HG-SFT）**。两集合通过感知哈希去重确保无重叠。

标注由 12 名标注员用定制的快捷键工具画两级框，5 名高级审校员独立复核，争议部分由主标注员裁决。标注者间 IoU 均值 0.86，Cohen's κ 达到 0.83，属于"高度一致"水平。

### 评测协议

关键创新：**页面感知的贪心匹配**。不把全文档所有框打平处理，而是逐页做 IoU ≥ 0.5 的贪心一对一匹配，按 IoU 降序分配，每个框最多参与一次匹配。

两个核心指标：

1. **FA（Answer-region F1）**：题目级定位的宏观平均 F1。先算每页 F1，再在样本内取均值，最后对所有样本取宏观平均。反映模型定位完整答案区域的能力。
2. **FμS（Step-level micro F1）**：步骤级定位的微观平均 F1，**只对包含步骤的页面计算**。这样做是因为步骤框分布极稀疏且不均匀——很多页根本没有步骤框，如果不做限制会把"没步骤的页"稀释掉信号。所有步骤页的 TP/FP/FN 全局累加后算一个统一 F1。

另外报告四个辅助指标：**FM_S**（步骤级宏观 F1，每个含步骤样本等权）、**Succ%**（JSON 解析成功率）、**S̄**（统一复合得分，解析失败的计 0，揭露格式错误的实际代价）、**Rep%**（输出重复率）。

### 基线评测

涵盖 9 个前沿 VLM 系统：

- **闭源 API**：GPT-5.4、Claude-Sonnet-4.6、Doubao-Seed-2.0-Pro（两个时间快照）、Gemini-3.0-Pro-Preview
- **开源权重**：Qwen3.5-397B-A17B（397B 参数，MoE 每 token 激活 17B）、GLM-5V-Turbo、Kimi K2.5、GLM-4.6V 9B
- **参考 SFT 系统**：GLM-4.6V 9B + HG-SFT（专项微调）

所有模型使用同一 prompt 模板，输出经格式宽容的 JSON 解析器处理，结构失败后有一次格式提醒重试机会。

### 核心发现

| 结论 | 数据支撑 |
|------|----------|
| 当前零样本前沿 VLM 远未解决该任务 | 最高仅 **55.22% FA / 48.22% FμS**（Doubao-Seed-2.0-Pro） |
| 步骤级定位是主导瓶颈 | 多数模型从 FA 到 FμS 急剧下降；GPT-5.4 从 14.91 掉到 **1.55**，Claude 从 16.83 掉到 **1.63** |
| 参数规模不解决问题 | 397B 的 Qwen3.5-397B-A17B 仅 **42.71/18.15**，不如多个小模型 |
| 少量领域微调即可大幅超越 | 9B 参考 SFT 系统用约 1 万样本微调 3 个 epoch（24 GPU 小时）达到 **74.97/72.26**，零样本最佳提升 +19.75/+24.04 |
| 数学和科学最差 | 非线性的分数推导、矩阵布局违反多数 VLM 的默认左→右、上→下空间先验 |
| 多页场景不稳定 | 页面数从 1 增到 3+，FμS 平均掉 25%+；模型出现"页面边界幻觉"（框归属到错误页面）和"跨页索引混乱" |
| 失败模式归类 | 遗漏步骤、框幻觉、步骤过分割/欠分割、页面错位、格式错误五大类 |

HG-Bench 远未饱和：500 个测试样本中，只有 **3 个（0.6%）** 被全部 9 个零样本基线同时做对，而 **115 个（23%）** 被所有基线全部漏掉。

### 局限

只涵盖中文 K-12 作业，未验证向其他语言或高等教育的迁移能力；500 样本限制了更细粒度的学科/年级分析；使用单一 IoU=0.5 匹配阈值；步骤分解存在不可避免的主观成分；参考 SFT 系统未使用强化学习，是否 RL 能进一步提升尚未探索。

## 三、对"AI 自讲 Demo"的实际启发

### 启发 1：两级定位是"AI 自讲"空间理解的基础能力

HG-Bench 最核心的设定——**题目级定位 + 步骤级分解**——和"AI 自讲 Demo"的需求高度吻合。"自讲"的本质是让 AI 不仅看到答案，还要理解答案的"结构"：哪部分是最终结果，哪部分是推导过程，推导的先后顺序是什么。

**直接映射：**
- 题目级框 → AI 需要知道"学生当前在讲哪道题"
- 步骤级框 → AI 需要知道"这道题分了几个步骤，现在讲到了哪一步"
- 有序步骤 → AI 需要按书写顺序逐步讲解，不能跳步或倒序

### 启发 2：页面感知是"多页讲解"不可回避的问题

论文发现模型在跨多页时会出现"页面边界幻觉"和"跨页索引混乱"——同样的现象放在"AI 自讲"场景中就是：AI 以为某步推导在第一页，但实际上在第二页；或者把跨页连续推导的步骤顺序搞反。

**这意味着：** 自讲 Demo 在处理多页作业时，必须显式维护"页感知"能力，不能把多页简单拼接成一张长图。每页的坐标空间是独立的，跨页的步骤顺序需要模型或工程逻辑来保证连续性。

### 启发 3：当前 VLM 在"结构定位"上远不可靠，需工程兜底

论文实验清楚表明，即便是 GPT-5.4 这样的前沿模型，在没有专项微调的情况下，步骤级定位 FμS 只有个位数（1.55）。这意味着**如果"AI 自讲"依赖 VLM 自己来识别答题结构，在真实作业上大概率会失败**。

**工程策略建议：**
1. **专用检测模型做前置定位**：先用一个目标检测或 Layout 分析模型（如微调后的 GLM-4.6V 或 YOLO 变体）做框检测，把答案区域定位出来，再交给讲解侧模型处理。
2. **Prompt + Schema 约束**：论文用精心设计的 JSON schema prompt 来约束输出格式，解析失败有一次重试机会。这种模式可以直接借鉴到自讲 Demo 中——让 VLM 输出结构化的 JSON 约束结果而非自由文本。
3. **后处理纠错**：论文提出了五种失败模式（遗漏、幻觉、欠/过分割、错页、格式错），自讲 Demo 的工程侧应该实现对应的校验和回退逻辑。

### 启发 4：少量领域数据微调性价比极高

论文最抓人的数字：**9B 模型 × 1 万样本 × 24 GPU 小时 = 超越所有闭源 API**。这对"AI 自讲 Demo"意味着：

- 如果 Demo 有针对性的标注数据（比如人工标注的答题结构），少量微调的效果可能远超换更大的通用模型。
- 微调用的训练数据（HG-SFT，约 1 万样本）也可以直接复用——因为 HG-Bench 的标注协议（两级框、有序步骤、包含约束）和自讲场景的需求几乎一样。
- 初始版本可以先用 GLM-4.6V 9B 或类似的开放权重模型做基础，在 HG-SFT 上微调作为起点，后续再补充自己的领域数据。

### 启发 5：评测指标的分离设计值得借鉴

论文把题目定位（FA）和步骤分解（FμS）解耦评测，这个思路可以迁移到自讲 Demo 的评估上：

- **答案识别率**：AI 能否正确找到学生写了解答的位置
- **步骤完整性**：AI 能否识别出完整的推理链条，没有漏步
- **顺序正确性**：AI 讲解的步骤顺序是否和实际书写顺序一致
- **跨页连贯性**：多页作业讲解时，跨页的步骤衔接是否正确

四个维度分开打分，比单一准确率指标更能指导优化方向。

### 启发 6：注意数学/科学类答案的"空间特殊性"

论文指出模型在数学和科学科目上表现最差，原因是分数推导、矩阵、草稿等布局不是简单的线性排列。这对自讲 Demo 意味着：

- 数学题的讲解需要更强的空间感知能力，不能假设"从左到右、从上到下"就能解读推导过程
- 可能需要额外的前置逻辑来把非线性的推导结构（如分步演算、树状推导）重排成适合讲解的线性序列

### 合理性批判与不足

上述启发的主要局限在于：HG-Bench 是一个"区域定位"基准，而"AI 自讲 Demo"还需要**语义理解和自然语言生成**能力——仅仅知道答案在哪是不够的，还得能解释推导过程和评估对错。论文没有涉及语义理解或讲解生成，所以从定位到讲解之间存在一个"最后一公里"的 gap。另外，HG-Bench 针对中文 K-12 作业，如果自讲 Demo 的目标是英文或高等教育场景，直接迁移可能效果打折扣。
