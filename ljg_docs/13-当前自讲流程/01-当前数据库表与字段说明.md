# 当前自讲流程数据库表与字段说明

本文档根据当前代码中的 SQLAlchemy 模型和 Alembic 迁移整理，范围是 `backend/app/models/` 中已经注册的持久化表。

当前共有 12 张业务表：

| 表名 | 模型 | 用途 |
|---|---|---|
| `self_explain_questions` | `Question` | 自讲题目、评分点和提示素材 |
| `users` | `User` | 登录用户和角色 |
| `auth_sessions` | `AuthSession` | 登录会话令牌 |
| `sessions` | `Session` | 一次自讲学习会话的确定性状态 |
| `explanation_attempts` | `ExplanationAttempt` | 学生的一次自讲或语音输入尝试 |
| `audio_files` | `AudioFile` | 语音输入落盘后的音频文件索引 |
| `ai_evaluations` | `AIEvaluation` | AI 对学生答案的评价结果和校验记录 |
| `external_call_records` | `ExternalCallRecord` | AI/ASR 外部调用审计记录 |
| `support_events` | `SupportEvent` | AI 教学支持、追问和跟进内容 |
| `student_submissions` | `StudentSubmission` | 学生对疑问、引导题或申诉的提交 |
| `state_transition_events` | `StateTransitionEvent` | 会话状态变化前后的快照 |
| `session_events` | `SessionEvent` | 会话级有序事件日志 |

`Question` 模型对应的表名是 `self_explain_questions`，不会另外生成一张名为 `questions` 的表。

## 1. `self_explain_questions`

题库表。题目中的评分点、常见错误、提示和完整解答都存放在这里，AI 评价和教学阶段会读取这些内容。

| 字段 | 类型 | 可空 | 说明 |
|---|---|---:|---|
| `id` | integer | 否 | 题目主键 |
| `tiku_question_id` | integer | 是 | 外部题库中的题目编号，唯一 |
| `question_content` | long text | 否 | 题目正文 |
| `standard_answer` | long text | 是 | 标准答案 |
| `rubric_points` | JSON 数组 | 是 | 评分点列表；有值时通常使用完整评分模式 |
| `common_errors` | JSON 数组 | 是 | 常见错误描述 |
| `alternative_solutions` | JSON 数组 | 是 | 可接受的替代解法 |
| `layered_hints` | JSON 数组 | 是 | 分层提示内容 |
| `guided_questions` | JSON 数组 | 是 | 引导式追问模板 |
| `full_solution` | long text | 是 | 完整解答，达到支持上限时可展示 |
| `grade_period` | smallint | 是 | 学段或年级信息 |
| `subject` | varchar(20) | 是 | 学科 |
| `q_type` | smallint | 是 | 题型编码 |
| `difficulty_level` | smallint | 是 | 难度等级 |
| `review` | varchar(2048) | 是 | 题目审核备注 |
| `topics` | long text | 是 | 知识主题或标签文本 |
| `method` | long text | 是 | 解题方法文本 |
| `archived_at` | datetime | 是 | 归档时间；为空表示未归档 |
| `created_at` | datetime | 否 | 创建时间 |
| `updated_at` | datetime | 否 | 最后更新时间 |

## 12. `session_events`

会话级事件日志。`seq` 在单个会话内单调递增，是当前设计中用于重建事件顺序的主要依据。

| 字段 | 类型 | 可空 | 说明 |
|---|---|---:|---|
| `id` | integer | 否 | 数据库主键 |
| `session_id` | integer | 否 | 关联 `sessions.id` |
| `seq` | integer | 否 | 会话内单调递增序号；同一会话内唯一 |
| `event_id` | varchar(64) | 否 | 事件业务 ID，全局唯一 |
| `run_id` | varchar(64) | 是 | 一次模型或业务运行的关联 ID |
| `parent_event_id` | varchar(64) | 是 | 父事件业务 ID |
| `event_type` | varchar(40) | 否 | 事件类型，如 `user.message`、`model.requested` 或 `state.changed` |
| `occurred_at` | datetime | 否 | 事件发生时间 |
| `data` | JSON | 否 | 事件载荷 |

当前表约束包括：

- `(session_id, seq)` 唯一，保证一个会话内不会重复使用序号。
- `event_id` 唯一。
- `seq >= 0`。
- 已建立按会话、运行 ID 和事件类型查询的索引。

## 表之间的主要关系

```text
users
  ├─ auth_sessions
  └─ sessions
       ├─ self_explain_questions
       ├─ explanation_attempts
       │    └─ audio_files
       ├─ ai_evaluations
       │    └─ external_call_records
       ├─ support_events
       ├─ student_submissions
       ├─ state_transition_events
       └─ session_events
```

这里的关系图只表示主要外键方向。`state_transition_events` 中的 `related_*` 字段目前主要承担审计关联作用，不都声明为数据库外键。

## 与当前自讲流程的对应关系

1. 题目从 `self_explain_questions` 读取。
2. 创建一条 `sessions` 记录，初始化轮次、状态和计数器。
3. 学生提交文本或语音，输入事实保存到 `explanation_attempts`；语音文件索引保存到 `audio_files`。
4. 后端调用 AI，调用过程写入 `external_call_records`，结构化评价写入 `ai_evaluations`。
5. 确定性规则根据评价结果更新 `sessions`，并把变化写入 `state_transition_events`。
6. 如果需要提示、纠错、追问或跟进，内容写入 `support_events`；引导答案等学生后续输入写入 `student_submissions`，部分内容还会回填到 `support_events.guided_answers`。
7. 同时，流程相关事件写入 `session_events`，其 `seq` 用于事件查询、轨迹构建和后续上下文排序。

## 当前排序缺口

`ExplanationAttempt` 可以通过 `run_id` 间接关联到 `session_events.seq`。`SupportEvent` 没有对应字段，且部分记录的 `evaluation_id` 为空，因此不能稳定地映射到事件序列。

当前实现仍可能使用 `created_at` 和记录 ID 生成合成顺序。这个顺序可以用于兼容历史数据，但不能完全替代会话级 `seq`。如果要修复新数据的排序问题，同时尽量少改动现有结构，候选方案是给 `support_events` 增加一个可空的 `created_seq` 字段，并在创建支持记录时保存当时的会话事件序号。

## 口径说明

- 本文档描述的是当前代码模型，不等于某个已经运行的生产数据库的实时结构。
- 如果数据库曾经执行过旧迁移，表中可能仍有模型已经删除的历史列。部署或迁移前，应以 `alembic upgrade head` 和实际数据库结构检查为准。
- JSON 字段中的内部键不属于数据库列，本文只说明字段用途，没有展开每个 JSON 对象的完整契约。
